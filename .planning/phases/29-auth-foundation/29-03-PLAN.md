## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-14 | Elevation of Privilege | guarded route reachable without session | mitigate | Every web_router route plus index and item_detail carry `Depends(require_auth)`. Verified by integration tests + manual checkpoint. |
| T-29-15 | Elevation of Privilege | bypass via api_router | mitigate | All existing /api/* routes (except /health) keep `Depends(require_api_key)`. Two scan endpoints gain `require_session_or_api_key`. /api/health is the only fully open endpoint. |
| T-29-16 | Denial of Service | health endpoint abused | accept | /api/health is intentionally open for platform health checks; rate limiting (Phase 31 SEC-02) applies elsewhere. |
| T-29-17 | Information Disclosure | nav exposes the email of the signed-in user to anyone with the cookie | mitigate (by design) | Email is only rendered to the cookie holder; httpOnly + signed cookie defends the cookie itself (T-29-01, T-29-03). |
| T-29-18 | Tampering | open redirect via `next=` | mitigate | `_safe_next()` from Plan 02 already restricts `next` to relative paths starting with a single `/`; the AuthRedirect handler in Plan 01 URL-encodes the path. |
| T-29-19 | Spoofing | session fixation | mitigate | On successful login/signup, `request.session["user_id"]` is set on the existing session — Starlette regenerates the cookie value on session changes. Acceptable for Phase 29; revisit in Phase 31 if needed. |
