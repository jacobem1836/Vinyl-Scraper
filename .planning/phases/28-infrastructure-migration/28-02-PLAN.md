<task type="auto">
  <name>Task 2: Dump Railway PostgreSQL data</name>
  <files>.planning/phases/28-infrastructure-migration/railway-dump.sql</files>

    - .planning/phases/28-infrastructure-migration/28-CONTEXT.md

  <action>
Dump the Railway PostgreSQL database to a local SQL file.

Steps:
1. Get the Railway DATABASE_URL: `railway variables --service Postgres` (or fetch from Railway dashboard if Railway CLI is not installed)
2. Export it: `export RAILWAY_DB_URL="postgresql://..."`
3. Run pg_dump (use --no-owner --no-privileges so it restores cleanly into Neon's role model):

```
pg_dump "$RAILWAY_DB_URL" \
  --no-owner \
  --no-privileges \
  --format=plain \
  --file=.planning/phases/28-infrastructure-migration/railway-dump.sql
```

4. Capture row counts for verification (write to a notes file):

```
psql "$RAILWAY_DB_URL" -c "SELECT 'wishlist_items' AS t, COUNT(*) FROM wishlist_items UNION ALL SELECT 'listings', COUNT(*) FROM listings;" \
  > .planning/phases/28-infrastructure-migration/railway-rowcounts.txt
```

5. Verify the dump file is non-empty: `test -s .planning/phases/28-infrastructure-migration/railway-dump.sql`

If pg_dump is not installed locally: `brew install libpq && brew link --force libpq` (macOS).

Add to `.gitignore` (append, do not overwrite): `.planning/phases/28-infrastructure-migration/railway-dump.sql` and `.planning/phases/28-infrastructure-migration/railway-rowcounts.txt` — these contain potentially sensitive data and shouldn't be committed.
  </action>
  <verify>
    <automated>test -s .planning/phases/28-infrastructure-migration/railway-dump.sql && grep -q "CREATE TABLE" .planning/phases/28-infrastructure-migration/railway-dump.sql && test -s .planning/phases/28-infrastructure-migration/railway-rowcounts.txt</automated>
  </verify>

  <action>
Restore the Railway dump into the Neon database, then verify row counts match exactly.

1. Use the Neon DATABASE_URL provided in Task 1's resume signal. Export it:
   `export NEON_DB_URL="postgresql://user:pass@ep-xxx.region.aws.neon.tech/dbname?sslmode=require"`
   (Use the **unpooled** endpoint for restore — pooled endpoints can stall long transactions.)

2. Restore the dump:
```
psql "$NEON_DB_URL" -f .planning/phases/28-infrastructure-migration/railway-dump.sql
```

3. Capture row counts on Neon:
```
psql "$NEON_DB_URL" -c "SELECT 'wishlist_items' AS t, COUNT(*) FROM wishlist_items UNION ALL SELECT 'listings', COUNT(*) FROM listings;" \
  > .planning/phases/28-infrastructure-migration/neon-rowcounts.txt
```

4. Diff the row counts — they MUST match exactly:

```
diff .planning/phases/28-infrastructure-migration/railway-rowcounts.txt .planning/phases/28-infrastructure-migration/neon-rowcounts.txt
```
Diff must produce zero output (identical files, modulo cosmetic whitespace — strip if needed).

5. If counts differ, STOP and report. Do not proceed to Plan 03 with mismatched data.

6. Also add `neon-rowcounts.txt` to `.gitignore` if it contains sensitive query output (it shouldn't, but be safe).
