  <action>
Launch the app on Fly.io WITHOUT deploying yet (so we can set secrets first), then set all secrets, then deploy.

Step 1 — Launch (no deploy):
```
flyctl launch --no-deploy --copy-config --name crate --region syd
```

If `crate` is taken, flyctl will prompt for an alternate name. Accept its suggestion (e.g. `crate-1234`). The new name will be written to fly.toml.

Notes on flags:
- `--no-deploy`: don't deploy yet (we need secrets set first or APScheduler crashes on missing DATABASE_URL)
- `--copy-config`: keep the fly.toml from Plan 01 as-is (do NOT regenerate)
- `--name`: prefer `crate`; accept fallback if taken
- `--region syd`: closest to user

Step 2 — Set all eight secrets in one command (atomic, one restart):

```
flyctl secrets set \
  DATABASE_URL="<NEON_POOLED_URL_FROM_PLAN_02>" \
  API_KEY="<from local .env>" \
  DISCOGS_TOKEN="<from local .env>" \
  EBAY_APP_ID="<from local .env>" \
  EBAY_CERT_ID="<from local .env>" \
  RESEND_API_KEY="<from local .env>" \
  RESEND_FROM="<from local .env>" \
  NOTIFY_EMAIL="<from local .env>"
```

Use the **pooled** Neon URL — FastAPI + SQLAlchemy benefit from connection pooling, and Fly machines are short-lived.

Step 3 — Verify all secrets are set:
```
flyctl secrets list
```
Output must list all eight names (values are hidden as digests, that's expected).

Step 4 — Deploy:
```
flyctl deploy
```

Wait for the build to complete and the health check to pass. flyctl prints `deployed successfully` on success.

Step 5 — Capture app URL:
```
flyctl status
```
Note the `Hostname` (e.g. `crate.fly.dev`) for Task 3.

Step 6 — Tail logs briefly to confirm APScheduler started:
```
flyctl logs --no-tail | head -100
```
Look for: `Started scheduler` or APScheduler-related startup logs (per app/scheduler.py).
